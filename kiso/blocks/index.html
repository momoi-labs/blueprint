Theme selector

Three states, in a settings row: name on the left, control flushed right.

Theme

Icon-only, so it fits a toolbar or a sidebar footer. Each button carries an aria-label and a tooltip — a monitor glyph for "system" is a convention, not self-evident.

The state model

System
no attribute — color-scheme follows the OS
Light
data-theme="light"
Dark
data-theme="dark"

System is the default. An explicit choice is what gets stored, and it survives a reload. "System" is not a third colour — it is the absence of a choice, which is why it is a state and not a checkbox.

Live check

Pick System, then change your OS appearance — the page follows without a reload. That is what separates a real system mode from one that reads the preference once at boot.

Where hatch must not go

Behind table rows, log output, charts, or any value the operator has to read. Hatch competes with dense text, and a decorative texture behind data is exactly the "flashy" the brand doc rules out. If it is loud enough to notice while reading, it is in the wrong place.
